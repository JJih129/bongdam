# 보고서 자료 — 봉담 안전지도 대작전 모바일/태블릿 대응

## 스크린샷 목록

같은 조건에서 **개선 전(`c4e62df`)** 과 **개선 후** 를 각각 찍었습니다.
파일명 규칙: `<기기>_<번호><화면>_<before|after>.png`

| 기기 | 해상도 | DPR | 입력 |
|---|---|---|---|
| `phone` | 874 × 300 | 3 | 터치 (아이폰 17 프로 가로, 사파리 UI 포함) |
| `tablet` | 1280 × 800 | 2 | 터치 (갤럭시 탭 가로) |
| `pc` | 1440 × 900 | 1 | 마우스 |

| 번호 | 화면 | 이 장면이 보여 주는 것 |
|---|---|---|
| 1 | 타이틀 | 폰: 버튼 89×20px → 163×43px 가로 한 줄 재배치 |
| 2 | 캐릭터 선택 | 폰: 최소 글자 9.6px → 11.5px |
| 3 | 게임 화면 | 카메라 시야·대사창 높이·초상화 크기·선생님 스프라이트 |
| 4 | 인벤토리 | **가장 대비가 큰 장면.** 탭 글자 세로 쪼개짐, 대사창이 하단을 가림, 토스트 겹침 |
| 5 | 안전지도 | 지도 148→267px, 좌우 여백 72% 회수, 세로 잘림 40px→0 |
| 6 | 업적 | 모달이 화면의 20% → 86%, 카드 잘림 해소 |

### 슬라이드에 쓰기 좋은 순서

1. `phone_4인벤토리_before` ↔ `phone_4인벤토리_after` — 문제 전체를 한 장으로 요약
2. `phone_3게임화면_before` ↔ `after` — 카메라·대사창·초상화
3. `phone_5안전지도_before` ↔ `after` — 레이아웃 재배치
4. `phone_1타이틀_before` ↔ `after` — 첫인상
5. `pc_3게임화면_before` ↔ `after` — **변화 없음**을 보여 주는 대조군

> `pc_*` 는 “PC는 손대지 않았다”를 증명하는 자료입니다. 두 장이 같아 보이는 것이 정답입니다.

## 재촬영 방법

```bash
node 검수도구/_shots.cjs <URL> <before|after> <phone|tablet|pc>
```

## 참고 — 검증 도구

| 도구 | 무엇을 재는가 |
|---|---|
| `qa.cjs all` | HUD 겹침 · 조이스틱 · 안내 링 · 탭 이동 · 콘솔 에러 |
| `_sweep.cjs` | 11개 화면을 하나씩 열어 작은 글씨·세로 쪼개짐·잘림·패널 크기 (`BD_MODE=phone\|tablet\|pc`) |
| `_tiny.cjs` | 화면 기준 11px 미만 글자 전수 (모달 연 상태 포함) |
| `_cpu.cjs` | CPU 4배 감속 + 느린 망에서의 로딩 (`BD_NET=1`) |
| `_blocktime.cjs` | 블록별 실행 시간 (`BD_TIME=1` 빌드 필요) |
| `_ux.cjs` | 탭 타겟 · 대비 · 정보 밀도 |
