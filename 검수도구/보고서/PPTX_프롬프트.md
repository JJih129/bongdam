## 붙여 넣을 프롬프트

```
「봉담 안전지도 대작전」 웹 게임의 모바일·태블릿 대응 작업 보고서를 pptx 로 만들어 줘.

■ 톤
  - 청소년 안전 교육용 게임 프로젝트의 개발 보고서. 발표 대상은 비개발자 포함.
  - 「무엇이 문제였고, 어떻게 확인했고, 얼마나 좋아졌는가」 순서.
  - 모든 주장에 숫자를 붙일 것. 추정치는 쓰지 말 것(아래 값은 전부 실측).
  - 과장 금지. 해결하지 못한 것도 마지막에 그대로 적을 것.

■ 슬라이드 구성 (14장)

1. 표지
   제목: 봉담 안전지도 대작전 — 모바일·태블릿 대응
   부제: 기기별 전용 UI 분리와 로딩 최적화
   기간/버전: v398 (Build 397)

2. 문제 정의
   PC 브라우저 기준으로 만든 게임을 링크로 배포했더니 폰에서 이런 일이 있었다.
   - 글자가 화면 기준 7.2px ~ 14.2px 로 제각각 (두 배 차이)
   - 버튼 글자가 「전 체」「소 모 품」처럼 한 자씩 세로로 쪼개짐
   - 모달이 화면의 20~22% 만 쓰면서 내용은 화면 밖으로 잘림
   - 대사창이 화면 높이의 39.8% 를 차지
   - 「W A S D 로 움직이세요」 같은 키보드 안내가 그대로 노출
   ▶ 첨부: phone_4인벤토리_before.png (문제 대부분이 한 장에 보임)

3. 접근 방법 — 「눈」이 아니라 「자를 대고」
   화면을 하나씩 열어 수치를 뽑는 검증 도구를 먼저 만들었다.
   - qa.cjs        : HUD 겹침 · 조이스틱 · 안내 링 · 이동 · 콘솔 에러
   - _sweep.cjs    : 11개 화면을 열어 작은 글씨/쪼개짐/잘림/패널 크기
   - _tiny.cjs     : 화면 기준 11px 미만 글자 전수
   - _cpu.cjs      : CPU 4배 감속(중급 폰 흉내) + 1.6Mbps 망에서의 로딩
   핵심: 세 기기(폰/태블릿/PC)에서 같은 검사를 돌려야 「한쪽만 좋아졌다」를 잡을 수 있다.

4. 기기 3계층 분리 (표)
   구분        | 폰                | 태블릿             | PC
   판정 기준    | 터치 · 높이 ≤520px | 터치 · 높이 >520px | 비터치
   키보드→터치  | 적용              | 적용               | 미적용
   글자 하한    | 11.5px            | 12px               | 원본 유지
   3단계 크기   | 적용              | 미적용             | 미적용
   모달 크기    | 화면의 90%        | 상한만 완화        | 원본 유지
   지도 재배치  | 2열               | 미적용             | 미적용
   카메라 줌    | 1.34배            | 1.0                | 1.0
   판정은 한 곳에서만 하고 <html> 클래스로 내보낸다 →
   PC 에는 규칙이 「아예 적용되지 않는다」가 측정으로 증명됨.

5. 카메라 시야 (Before/After)
   currentScale 이 짧은 축을 기준으로 잡아, 가로로 긴 폰에서는 가로만 늘어났다.
     PC 1440x900   보이는 월드 0.736 x 0.614
     폰 874x300    보이는 월드 1.341 x 0.614  ← 월드 폭은 1.0 뿐
   즉 「맵 밖 여백」을 34% 나 채우면서 모든 것이 작게 그려졌다.
     문화의집 선생님 스프라이트  PC 139x139px → 폰 46x46px (정확히 1/3)
   개선: 가로 1.341 → 1.000, 선생님 46 → 62px (+35%), PC·태블릿 무변화
   ▶ 첨부: phone_3게임화면_before.png / _after.png

6. 대사창·초상화
   대사창 높이의 64% 가 패딩(42+44px)이었다 — PC 상자(234px) 기준 고정값이 그대로 남음.
     대사창  화면 높이의 39.8% → 17.3%
     초상화  화면 높이의 86%  → 61.9%

7. 안전지도 재배치
   지도판이 804px 패널 가운데 228px 정사각으로 놓여 좌우 288px씩(72%)이 빈 공간인데
   세로로는 40px 이 잘리고 있었다 — 정확히 반대로 하고 있었다.
   좁은 화면에서만 2열 격자로 바꿔 머리·발을 옆으로 보내고 높이를 전부 지도에 줌.
     지도 148x148 → 267x267 (1.8배) · 세로 잘림 40px → 0
   ▶ 첨부: phone_5안전지도_before.png / _after.png

8. 글자 크기 통일
   원인이 둘이었다.
     (1) 패널마다 선언 크기가 11~17px 로 달랐다
     (2) 「작은 글씨 보정」을 컨테이너 zoom 으로 걸어 패널 전체가 커졌고,
         배율이 0.65 / 0.78 / 0.822 / 0.885 / 1.095 로 갈라졌다
   → zoom 을 버리고 「화면 기준」 글자 크기만 지정. 3단계로 통일.
     7.2 ~ 14.2px (제각각)  →  11.5 / 12.5 / 14.5px
     화면 기준 11px 미만 글자: 가방 2개·지도 10개 → 0개
     글자 세로 쪼개짐: 6개 → 0개
   ▶ 첨부: phone_4인벤토리_before.png / _after.png

9. 모달 전반 + 타이틀
   대부분이 같은 컨테이너(.bd-modal-box)를 써서, 하나를 고치니 여덟 화면이 함께 따라왔다.
     모달 크기        화면의 20~22% → 84~86%
     탭 타겟 44px 미만  기본 4개→2개 · 가방 10개→2개
     타이틀 버튼      89x20px → 163x43px (가로 한 줄 재배치)
     타이틀 최소 글자  7.0px → 11.5px
   ▶ 첨부: phone_1타이틀_before.png / _after.png, phone_6업적_before.png / _after.png

10. PC 는 손대지 않았다 (대조군)
    같은 검사를 PC 1440x900 에서 돌린 결과:
      html.bd-mobile-ui = false · 모바일 스타일 0개 주입 · 카메라 줌 1.0
      키보드→터치 변환 블록 자체가 실행되지 않음
    ▶ 첨부: pc_3게임화면_before.png / _after.png  (두 장이 같아 보이는 것이 정답)

11. 로딩 최적화 — 어디에 시간이 가는지 먼저 쟀다
    블록별 실행 시간을 계측한 결과, 「실행」은 다 합쳐 513ms 인데
    마지막 블록이 끝나는 건 3,124ms 였다. 즉 대부분이 「파싱」이었다.
    → 코드를 고치는 게 아니라 파싱할 양을 줄이는 것이 답.

12. 로딩 최적화 — 결과
    index.html   3,573KB → 2,685KB (주석·공백 제거, 실제 파서 사용)
    brotli 전송   600KB → 427KB (-29%)
    폰트          3벌 504KB → 2벌 368KB (900 굵기 제거, 700 로 대체)
    타이틀 진입   3,959ms → 3,211ms (-18%)   ※CPU 4배 감속
    느린 망(1.6Mbps) 7,067ms → 6,302ms (-18%)

13. 검증 결과 요약
    qa.cjs all           전부 통과 · 콘솔 에러 0
    11개 화면 스윕        폰 0건 · 태블릿 0건 (경고 없음)
    키보드 문구 변환      49개 중 48개 (남은 1개는 에디터 전용 마크업으로 화면에 안 나옴)

14. 남은 과제 (솔직하게)
    - 전투 화면(HSR)과 미니게임 내부는 진입 조건이 있어 이번 자동 검사에 잡히지 않음
    - 태블릿은 화면을 성기게 씀 (정보 밀도 0.10 vs 폰 0.66 글자/1000px²) — 고장은 아니나 개선 여지
    - PC 일부 글자 10.5px — 원본 상태이며 이번 범위 밖
    - 「JS 외부 파일 분리」는 index.html 을 275KB 까지 줄이는 큰 이득이 있었으나
      실행 순서가 바뀌며 회귀가 두 번 나 보류함 (도구는 남겨 둠)

■ 디자인 요청
  - 16:9. 표지·간지는 게임의 색(짙은 남색 #0f1526, 포인트 #ffd86b)을 쓸 것.
  - Before/After 는 좌우 2단으로 크게. 캡션에 수치를 병기.
  - 표는 최대 6행. 숫자는 오른쪽 정렬.
  - 아이콘·이모지 남용 금지. 본문 18pt 이상.
```
